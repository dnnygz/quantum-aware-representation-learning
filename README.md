# Quantum-Aware Representation Learning

This repository studies quantum-aware representation learning for TCGA-BRCA
ER-status classification using small variational quantum classifiers (VQCs).
The Python distribution is named `quantum-aware-representation-learning`;
the existing `src.data` and `src.phase2` module paths are unchanged.
The frozen **Phase 1A--1C** includes the post-hoc complementary XGBoost baseline.
Phase 2 explores fixed PCA and trainable encoder representations with VQCs and
classical controls; see the [A/B protocol](docs/phase2_ab.md) and
[pilot report](reports/phase2/pilot_fold0_50e_verified/report.md).
Canonical cohort **v1** constructs an auditable, patient-level dataset for
predicting baseline estrogen receptor status (ER-positive versus ER-negative)
of the primary breast tumour from RNA expression.

The target is **ER status in patients already represented in TCGA-BRCA**. It is
not a cancer-diagnosis task, a screening tool, or a clinical decision system.
No claim of quantum advantage is made.

## Data source and cohort definition

The sole primary source is the official [NCI Genomic Data Commons
(GDC)](https://portal.gdc.cancer.gov/) project TCGA-BRCA. The acquisition query
requests open-access, Primary Tumor, RNA-Seq gene-expression files generated by
the `STAR - Counts` workflow. The exact API payload, response metadata, release,
file UUIDs, sizes and GDC MD5 checksums are saved with every snapshot.

ER is not inferred from expression. Canonical v1 uses the direct patient-level
TCGA Clinical Supplement XML field `er_status_by_ihc` /
`breast_carcinoma_estrogen_receptor_status` (CDE 2957359). `Positive` maps to
`1` and `Negative` to `0`; missing, not-evaluated, indeterminate, equivocal or
unsupported baseline values are excluded. Measurements from recurrence,
metastasis, follow-up or new-tumour events never impute a missing baseline ER.
The immutable binary convention is `ER_positive = 1` as the positive class and
`ER_negative = 0`; its machine-readable contract is
[`configs/label_semantics.yaml`](configs/label_semantics.yaml).

The BCR patient Biotab is an exact consistency cross-check. Harmonized GDC
`ESR1`/`IHC` molecular-test nodes are retained only as secondary validation.
The justification is in [the ER source audit](reports/data/er_source_audit.md).
The earlier unrestricted harmonized cohort is preserved with provenance and
hashes as superseded `v0_harmonized_esr1_ihc`; [the version comparison](reports/data/old_cohort_vs_baseline_er_cohort.md)
records every patient entry, exit and label change.

Inclusion requires:

- a TCGA-BRCA case;
- at least one open Primary Tumor `STAR - Counts` RNA-Seq file;
- a binary baseline ER IHC result in the Clinical Supplement XML;
- a concordant BCR patient Biotab cross-check;
- a successfully downloaded, MD5-verified expression file;
- valid, finite `unstranded` counts with a gene schema shared by the cohort.

When a case has multiple eligible files, selection is outcome-blind and
deterministic: candidates are ordered by sample barcode, portion number,
aliquot barcode, sample UUID, then file UUID. The first candidate is retained;
all candidates and the decision are written to the sample-selection audit.
This stable rule avoids cherry-picking but is not a claim that the selected
aliquot is biologically superior. See [scientific decisions](docs/data_decisions.md).

## Expression representation

The processed matrix contains raw GDC STAR `unstranded` gene counts, indexed by
case UUID. GDC documents that its harmonized RNA-seq analysis treats reads as
unstranded. Technical summary rows (`N_*`) are excluded from the feature matrix
and recorded by the parser. Versioned Ensembl gene IDs are the feature keys;
gene symbols and gene types are stored separately in `genes.parquet`.

The canonical matrix remains raw and immutable. Phase 1B implements a reusable
training-fold transform: genes with CPM >= 1 in at least 10% of training
patients, frozen-reference TMM, log2-CPM with a library-size-adjusted prior,
and exact-zero-variance removal. The threshold is a prespecified scientific
decision, not optimized from ER or model performance. Every learned parameter
uses `fit(training)` and is frozen for `transform(validation/test)`; no global
normalized modeling matrix is created. Estimator-specific scaling is available
but is fit later inside each model pipeline.

## Reproduce Phase 1

Python 3.10--3.13 is supported. The full expression download is several GB;
ensure sufficient disk space.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'

# Inspect API metadata and create a release-scoped snapshot without large files
python -m src.data.download --metadata-only

# Download one deterministically selected file per RNA-seq case with valid ER
python -m src.data.download

# Link clinical data, build the patient matrix, validate it and create splits
python -m src.data.cohort

# Fit and audit fold-local RNA-seq preprocessing states (no models)
python -m src.data.preprocessing

# Create/audit Phase-1C development-only inner CV (still no models)
python -m src.data.phase1c_protocol

# After protocol approval: development-only selection, then one locked-test run
python -m src.data.classical_baseline --stage cv
python -m src.data.classical_baseline --stage final

# Audit class semantics from persisted predictions; no fitting or inference
python -m src.data.phase1c_semantic_audit

# Reproduce the separately labelled post-hoc XGBoost baseline
python -m src.data.xgboost_protocol
python -m src.data.xgboost_baseline --stage cv
python -m src.data.xgboost_baseline --stage final

# Equivalent complete workflow
make data

# Re-run the independent ER-source audit when explicitly reviewing sources
make audit-er
```

`data/raw/gdc_release_<version>/query_<hash>/` is immutable. The query/config
hash prevents two cohort definitions from sharing a raw directory. Re-running
verifies/reuses matching files. A different release or query creates a new
snapshot; differing content at an existing immutable path raises an error. Use
`--config` on both commands to select a non-default configuration.

## Outputs

Successful cohort construction writes:

- `data/processed/expression.parquet` — patients × versioned Ensembl genes;
- `data/processed/labels.parquet` — binary ER labels;
- `data/processed/metadata.parquet` — selected file/sample/case lineage;
- `data/processed/genes.parquet` — Ensembl ID, symbol and gene type;
- `data/processed/splits.json` — reusable train/test and stratified folds;
- `data/interim/sample_selection_audit.parquet` — all candidate decisions;
- `reports/data/cohort_summary.json` — inclusion/exclusion flow;
- `reports/data/qc_report.json` — automated quality checks;
- `reports/data/provenance.json` — queries, release, hashes and software;
- `reports/data/old_cohort_vs_baseline_er_cohort.json` — version comparison;
- `data/processed/versions/superseded/v0_harmonized_esr1_ihc/` — prior cohort.
- `data/interim/preprocessing/phase1b_primary_v1/<partition>/` — fitted masks,
  frozen TMM state and per-training-sample QC, but no normalized matrix;
- `reports/data/preprocessing_qc.json` — per-partition Phase-1B QC and runtimes;
- `reports/data/preprocessing_provenance.json` — Phase-1B hashes and provenance;
- `reports/data/preprocessing/ma_plots/` — training-only MA diagnostics.
- `data/processed/splits/phase1c_inner_cv.json` — official development-only
  inner folds for classical model selection;
- `reports/data/phase1c_protocol_qc.json` — locked-test isolation and split QC;
- `docs/phase1c_protocol.md` — frozen prespecified model-selection protocol;
- `reports/data/phase1c_classical_baseline.md` — durable Phase-1C results and
  interpretation;
- `reports/data/phase1c_cv_results.csv` — every model/C/fold result;
- `data/processed/phase1c_classical_baseline_v1/oof_predictions.parquet` and
  `locked_test_predictions.parquet` — reusable patient-level predictions;
- `reports/data/phase1c_provenance.json` and `phase1c_leakage_qc.json` — hashes,
  software, split identity and leakage controls.
- `reports/data/phase1c_label_metric_semantic_audit.json` — read-only
  reconciliation of `ER+=1`, `ER−=0`, class-specific AP and named confusion
  cells.
- `reports/data/xgboost_posthoc_locked_test_performance.json` — separately
  labelled post-hoc XGBoost performance and paired bootstrap comparisons;
- `reports/data/phase1_final_freeze.md` — final Phase-1 freeze, integrity
  checks, versions and reconstruction hashes.

Generated counts are deliberately not stated in source code or documentation;
they belong to the release-specific reports.

## Project status and next phases

Phase 1 is closed and frozen. Canonical v1 implements acquisition, baseline Clinical Supplement ER
labeling, XML/Biotab/harmonized-source checks, clinical/expression linkage,
patient-level deduplication, QC, reusable splits, version comparison and
provenance. Phase 1B adds leakage-safe RNA-seq preprocessing components and
per-partition fitted state. Phase 1C adds four regularized classical reference
models selected exclusively by development-only inner CV and evaluated once on
the locked test. Logistic L1 remains the primary full-representation reference
(`ROC-AUC=0.9660`). Phase 1C-XGB adds a separately labelled post-hoc
complementary tree baseline without retroactively changing that choice. See
the [final freeze](reports/data/phase1_final_freeze.md).
Phase 2 implements the development A/B pilot with PCA representations, a
trainable encoder, and ideal small VQCs. See the [analysis guide](notebooks/README_representation_analysis.md)
for read-only exploration of saved results. These pilot observations do not
establish quantum advantage. The locked-test predictions and paired bootstrap
indices remain frozen references.
