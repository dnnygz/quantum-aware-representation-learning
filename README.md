# Reproducible TCGA-BRCA ER-status cohort for NISQ VQC research

This repository supports a thesis on variational quantum classifiers (VQCs)
under NISQ constraints. The current implementation is **Phase 1 only**: it
constructs an auditable, patient-level cohort for predicting estrogen receptor
status (ER-positive versus ER-negative) from breast-tumour RNA expression.

The target is **ER status in patients already represented in TCGA-BRCA**. It is
not a cancer-diagnosis task, a screening tool, or a clinical decision system.
No claim of quantum advantage is made.

## Data source and cohort definition

The sole primary source is the official [NCI Genomic Data Commons
(GDC)](https://portal.gdc.cancer.gov/) project TCGA-BRCA. The acquisition query
requests open-access, Primary Tumor, RNA-Seq gene-expression files generated by
the `STAR - Counts` workflow. The exact API payload, response metadata, release,
file UUIDs, sizes and GDC MD5 checksums are saved with every snapshot.

ER is not inferred from expression. It is read from harmonized GDC clinical
`follow_ups.molecular_tests` records where `gene_symbol=ESR1` and the configured
method is `IHC`. `Positive` maps to `1`, `Negative` maps to `0`; missing,
unknown, equivocal, unsupported, or contradictory case-level observations are
excluded and reported. The original molecular-test records remain in the raw
snapshot.

Inclusion requires:

- a TCGA-BRCA case;
- at least one open Primary Tumor `STAR - Counts` RNA-Seq file;
- a concordant, binary ESR1 IHC result;
- a successfully downloaded, MD5-verified expression file;
- valid, finite `unstranded` counts with a gene schema shared by the cohort.

When a case has multiple eligible files, selection is outcome-blind and
deterministic: candidates are ordered by sample barcode, portion number,
aliquot barcode, sample UUID, then file UUID. The first candidate is retained;
all candidates and the decision are written to the sample-selection audit.
This stable rule avoids cherry-picking but is not a claim that the selected
aliquot is biologically superior. See [scientific decisions](docs/data_decisions.md).

## Expression representation

The processed matrix contains raw GDC STAR `unstranded` gene counts, indexed by
case UUID. GDC documents that its harmonized RNA-seq analysis treats reads as
unstranded. Technical summary rows (`N_*`) are excluded from the feature matrix
and recorded by the parser. Versioned Ensembl gene IDs are the feature keys;
gene symbols and gene types are stored separately in `genes.parquet`.

No PCA, supervised feature selection, dataset-wide scaling, or learned
normalization occurs in this phase. Any transformation that estimates
parameters must later be fit inside each training fold. Split files contain
patient IDs, so every classical and quantum model can reuse identical
partitions.

## Reproduce Phase 1

Python 3.10--3.13 is supported. The full expression download is several GB;
ensure sufficient disk space.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'

# Inspect API metadata and create a release-scoped snapshot without large files
python -m src.data.download --metadata-only

# Download one deterministically selected file per RNA-seq case with valid ER
python -m src.data.download

# Link clinical data, build the patient matrix, validate it and create splits
python -m src.data.cohort

# Equivalent complete workflow
make data
```

`data/raw/gdc_release_<version>/query_<hash>/` is immutable. The query/config
hash prevents two cohort definitions from sharing a raw directory. Re-running
verifies/reuses matching files. A different release or query creates a new
snapshot; differing content at an existing immutable path raises an error. Use
`--config` on both commands to select a non-default configuration.

## Outputs

Successful cohort construction writes:

- `data/processed/expression.parquet` — patients × versioned Ensembl genes;
- `data/processed/labels.parquet` — binary ER labels;
- `data/processed/metadata.parquet` — selected file/sample/case lineage;
- `data/processed/genes.parquet` — Ensembl ID, symbol and gene type;
- `data/processed/splits.json` — reusable train/test and stratified folds;
- `data/interim/sample_selection_audit.parquet` — all candidate decisions;
- `reports/data/cohort_summary.json` — inclusion/exclusion flow;
- `reports/data/qc_report.json` — automated quality checks;
- `reports/data/provenance.json` — queries, release, hashes and software;

Generated counts are deliberately not stated in source code or documentation;
they belong to the release-specific reports.


Notebooks do not contain hidden cohort logic. `01_tcga_cohort.ipynb` inspects
the generated summary and metadata; `02_eda.ipynb` performs label-distribution
and library-size QC only.

## Project status and next phases

Phase 1 implements acquisition, clinical/expression linkage, ER labeling,
patient-level deduplication, QC, reusable splits, and provenance. It does not
implement VQCs, PennyLane, Qiskit, feature selection, model tuning, or a
dashboard.

The next recommended phase is a leakage-safe classical baseline: define
fold-local count transformation/filtering and preprocessing, then evaluate
regularized logistic regression and SVM on the frozen patient splits before
designing any quantum feature budget or circuit.
